### R2.2 Program restructure (resolves P0-1): four Epics, Risk = High, Effort = XL
The single-Epic framing understated scope: the core silently bundles an event-sourced store, a package manager + permission system, a distributed concurrency layer, an IPC/sandbox runtime, an agent-security framework, and two production apps. Re-classify and split:
- **Effort: XL. Risk: High.** Primary risk is no longer only "harness drift" (domain leaking into core) but also **"harness omni-scope"** (core re-implementing solved infrastructure).
- **Epic A - Core substrate + state**: Skill/CLI contract, generic domain lifecycle/schemas (provisional, R2.7), SQLite-WAL durable state (R2.4), handoff/finalize/resume, actor identity/trust.
- **Epic B - Isolation, brokerage, security**: out-of-process workers, capability broker (MCP-aligned, R2.5), supply-chain attestation (AIBOM, R2.10), localhost UI hardening, spend ledger.
- **Epic C - Image reference domain pack**: Civitai/HF/AIR resolvers, workflow import, typed graph patches, Comfy Cloud thin-wrapper execution (R2.3), review gallery.
- **Epic D - `presentation_document_pack` production pack**: edit-based deck/doc generation (R2.8), source-native artifacts, review/finalize/handoff.
- Dependency order: A -> B -> {C, D}. Each Epic gets its own `/speckit-specify` cycle; do not collapse them into one Epic under the user's global workflow.

### R2.3 Comfy Cloud execution contract (resolves P0-2, P1-1): thin polling wrapper, not a re-implemented engine
- The image pack execution adapter binds to the **real Comfy Cloud API** (F-4): submit via `POST /api/prompt` (body `prompt` = API-format workflow graph, plus optional `extra_data`, `partial_execution_targets`); receive `prompt_id`; poll `GET /api/job/{id}/status`.
- **Canonical provider job status mapping** (replaces invented status names for the image pack): `waiting_to_dispatch|pending -> queued`, `in_progress -> running`, `completed -> succeeded`, `error -> failed`, `cancelled -> cancelled`. Store the raw provider status in `last_provider_status` and the mapped value in `job_manifest.json`.
- **Model/asset bootstrap is programmatic**: `POST /api/assets` accepts URL-based import (`url`, `name`, optional `tags`/`user_metadata`/`preview_id`) for Civitai/HF links; it is **content-addressed (hash dedup)** and returns 200 (exists) or 201 (new) with `created_new`. The harness uses `check-if-asset-exists-by-hash` as a natural idempotency key, satisfying Q24 without inventing a separate dedup mechanism.
- Auth = `X-API-Key` (key from platform.comfy.org/profile/api-keys); the harness stores only `credential_ref` (Q32/Q34 unchanged).
- Q25/Q26 scheduler scope shrinks: the core does **not** own a bespoke durable-execution engine for provider jobs; it owns lease + manifest persistence + a polling loop over the provider's own job model. Provider-side durability (the `prompt_id` lifecycle) is reused, not rebuilt.
- Open item for spec (low risk): confirm whether `POST /api/assets` URL import covers gated/private Civitai/HF resources via the harness key or requires Comfy Cloud-side stored secrets (R2.8 third-party credential boundary).

### R2.4 Durable state substrate (resolves P1-2): SQLite WAL + exported manifests
- **Decision: the first-version source of truth is SQLite in WAL mode** (F-11), not hand-rolled JSONL+file-lock+atomic-rename+checksum-chain. SQLite is an embedded single-file library, not a service, so it satisfies the "no service dependency / portable / inspectable / resumable" goals while providing ACID, concurrency, and crash recovery for free.
- **Event semantics preserved**: an append-only `event_log` table (monotonic id, `workspace_id`, `run_id`, `trace_id`, ts, actor, actor_trust, event_type, domain_pack_id, payload_hash, evidence_path). Append-only is enforced by application invariant + triggers; the audit chain (prev_hash/curr_hash) lives in columns.
- **Manifests become exported views**, not the primary store: `state export` writes the canonical JSON manifests + JSONL event log from SQLite for handoff/finalization/cross-agent resume. Boundary artifacts that must be plain files (final package, handoff package, evidence) remain plain files.
- This **deletes** the riskiest self-built mechanisms (cross-platform file locking, temp+rename atomicity on network FS, manual checksum chains, manual replay equivalence) and replaces them with SQLite guarantees. `snapshot_manifest.json`/`migration_ledger.json` (Q28) remain as **export/evolution** artifacts; `migration_ledger` maps to SQLite `user_version`/schema migrations.
- Scope constraint (from F-11): SQLite WAL is **same-host only**. Acceptable because the concurrency model is same-host (R2.6). Cross-machine collaboration is A2A, not shared SQLite.
- Audit-hash chain is not the old hand-rolled state substrate. SQLite-WAL supplies primary storage integrity/atomicity; `prev_hash`/`curr_hash`, snapshot checksums, and exported JSONL checksums are tamper-evidence for portable artifacts after export.

### R2.5 Protocol alignment (resolves P1-3): align, do not re-invent
- **Capability broker aligns to the MCP tool model** (F-9): scope/consent semantics mirror MCP "explicit consent before tool invocation" and "tool descriptions/annotations are untrusted unless from a trusted server" (the latter is identical to the plan's prompt-carrier boundary). Worker side-effect requests SHOULD map cleanly onto MCP tool-call shapes so an MCP transport can be a drop-in adapter rather than a parallel invented protocol.
- **MCP release-candidate review is architectural, not a version bump** (F-9): source-refresh must evaluate MCP Tasks against the harness provider-job/task model and MCP Apps against the AG-UI/localhost browser-surface model before adopting either. Until that review passes, the released 2025-11-25 spec remains the interop baseline and MCP stays optional.
- **Worker isolation** keeps the out-of-process boundary but targets a **standard transport** (MCP stdio, or WASI) rather than a bespoke IPC dialect, so the sandbox story reuses ecosystem tooling.
- **Remote/peer interop aligns to A2A v1.0.0** (F-3): peer-agent identity uses **signed Agent Cards** (not free-form strings); remote work uses A2A **task/artifact** semantics. The local actor identity/trust registry (Q30) is the same-host analogue of A2A signed Agent Cards.
- **Browser surfaces emit AG-UI-shaped events by project decision** (F-2): the localhost intake/review/resume surfaces use the AG-UI event vocabulary (messages, tool calls, state patches, lifecycle) so a real-time AG-UI client is an upgrade path, not a rewrite. Static HTML + one-time-token remains the durable fallback for offline review.
- Net effect: MCP/A2A/AG-UI become **project-selected alignment baselines**, with direct adapters as the performance path. This honors the "no MCP-server-as-core" guardrail in spirit, not just in letter; none of these protocols becomes a mandatory core runtime dependency.

### R2.6 Concurrency model (resolves P2-2): same-host, single-writer, sequential-handoff-first
- **Locked**: "cross-agent" means **same-host** agents (e.g. Codex, Claude Code) sharing one workspace directory, primarily via **sequential hand-off**, with **single-writer** safety for the rare concurrent case.
- The single-writer lease (Q26) maps directly onto **SQLite WAL's single-writer guarantee** + an ownership row; heartbeat/TTL/stale-recovery remain but are now backed by ACID rows, not network-fragile lock files.
- **Cross-machine concurrency is explicitly out of scope for v1** and is delegated to A2A (R2.5) if ever needed. This removes the contradiction between "sequential clean handoff" and "two agents racing over a network FS" and lets the over-built distributed-lock machinery shrink.
- Containerized same-host runs are allowed only when all cooperating agents see the workspace database through a local filesystem with reliable SQLite locking semantics on the same kernel/host. Docker Desktop remote volumes, network filesystems, cloud-sync folders, SSHFS/NFS/SMB, and any shared volume whose lock semantics cannot be proven are treated as cross-machine for SQLite purposes and must fail closed or use an A2A/export handoff instead.

### R2.8 Credential, entitlement, and source-native constraints (resolves P2-3 + new risks)
- **`credential_profile.json` gains `entitlement_tier`** (e.g. Comfy Cloud `Creator|Pro`): "live-first when credentials exist" (Q33) MUST also check entitlement, because model import + cloud execution are gated behind Creator/Pro tiers. A resolved key without the required tier fails closed with a setup prompt, not a runtime 403 mid-job.
- **Third-party credential boundary is explicit**: some provider credentials (e.g. Civitai/HF keys for private models) are stored on the **Comfy Cloud side (its Secrets store)**, outside harness control. `security_inventory.json` records this as an out-of-band credential dependency the harness cannot attest, and surfaces it to the creator instead of pretending to manage it.
- **Local custom models**: Comfy Cloud cannot ingest a local file directly (it imports from public Civitai/HF). The rights/license gate MUST catch the resulting trap (uploading a private LoRA to a public repo to use it) and block/clarify rather than silently proceed.
- **`presentation_document_pack` generation is edit-based** (F-6): artifacts are produced via programmatic OOXML tooling (PPTX/DOCX) and template/reference editing in the PPTAgent style, NOT by trusting the LLM to emit valid OOXML. Acceptance proof = editable source-native PPTX/DOCX/Markdown/HTML + static preview/export. This pack is sized as a true production app (comparable to the image pack), not a lightweight "proof" note.

### R2.10 Standards pinning (resolves P3-2)
- **AIBOM/SBOM format pinned at source-refresh**: external pack + worker-bundle attestation uses the latest verified CycloneDX ML-BOM-capable schema as the primary format (CycloneDX 1.7 on 2026-06-21; downgrade to 1.6 only if the selected tooling requires it and records why). SPDX 3.x AI/dataset profiles are accepted alternates (F-13). "SBOM/AIBOM required" everywhere in this plan means this source-refreshed pin.
- **OpenTelemetry is advisory, not load-bearing** (F-10): traces MAY follow GenAI semconv naming, but the SQLite-WAL state plus exported manifests are authoritative and the trace schema MUST NOT hard-depend on an unstable OTel revision.

The human gates (resume confirmation, creator-action, budget) are documented as the **final safety boundary**, with carrier-isolation policies as mitigations, not guarantees.

Source-refresh must review Sigstore/cosign-style provenance, Syft/Grype-style SBOM/vulnerability scanning, wasmtime/WASI or platform sandbox backends, and standard auth/crypto libraries. Any hand-rolled substitute for provenance, vulnerability scanning, sandboxing, auth, circuit breaking, or spend-ledger primitives requires an explicit build-vs-buy note in the spec.

### R2.11 Worker sandbox backend matrix & fail-closed (resolves the "sandbox is only a goal list" finding)
Out-of-process is necessary but not sufficient; the plan must NAME an enforced sandbox backend and fail closed when none is available.
- **Minimum guaranteed backend, by platform** (the worker adapter selects the first available, records which one, and refuses to run external code without one):
  - Cross-platform preferred: a **WASI runtime** (e.g. wasmtime) for packs compiled to WASM - deny-by-default capabilities, no ambient FS/network.
  - Linux: rootless container (bubblewrap / runc) OR seccomp-bpf + user/mount/network namespaces.
  - macOS: a Seatbelt profile (`sandbox-exec`) OR a container runtime.
  - Windows: a container OR AppContainer + Job Object limits.
- **Fail-closed rule (INV-18)**: if no verified sandbox backend is available for the host, EXTERNAL domain-pack workers MUST NOT run. Built-in reference packs may run trusted but still through the same worker interface. Each worker invocation records `sandbox_backend`, `policy_hash`, and the enforced limits (no ambient env, deny-by-default egress, read-only inputs, per-run temp root, realpath/symlink/`../` denial, archive/decompression + CPU/memory/fd/process/time limits, child-process kill-tree) into `M-sec-worker_sandbox_policy`, `M-core-security_inventory`, and evidence.
- This upgrades the existing "Worker sandbox boundary" list (in the 2026 Adversarial Review Lock) from aspirational language to an enforced precondition.

### R3-STD Standards basis & minimal-context load order (deep-researched, verified 2026-06-21)

### R3.4 Canonical lifecycle state machine (one model; domain aliases mapped)
Canonical states (`S-life-*`): `workspace_created -> domain_pack_selected -> intake_submitted -> inputs_resolved -> domain_plan_created -> domain_plan_validated -> preflight_checked -> execution_prepared -> (submitted|running|pending) -> artifacts_ready -> review_open -> human_action_required -> action_saved -> (continued|accepted|blocked|stopped) -> final_package_created -> handoff_refreshed -> completed`.
Transition guards: every transition appends `M-core-event_log`; mutating transitions require `R-gated_by` {lease, trust, budget where spend occurs, ui_session where browser-originated}. The table below is the implementation source; the arrow string above is only a compact summary.

### R3.5 Capability & permission taxonomy
Capabilities (`CAP-*`, the only privileged ops a worker may request via a side effect): `CAP-provider_call`, `CAP-llm_model_call`, `CAP-network_request`, `CAP-file_read`, `CAP-file_write`, `CAP-budget_spend`, `CAP-project_memory_write`, `CAP-external_tool_call`, `CAP-external_agent_task`, `CAP-localhost_ui_event`. Each is declared in `M-core-domain_pack_manifest`, granted in `M-core-domain_pack_registry`, narrowed per workspace, and denied by default if undeclared.
Retention classes (`final_package`, `project_memory`, `handoff_status`, `audit_event_log`, `snapshot`, `raw_intermediate`, `temp_render`, `provider_cache`) with proof-gated pruning per `M-core-retention_policy`.

### R3.7 Invariants (declarative axioms; positive form of the "Do not..." rules)
- INV-1: every side effect is performed by `E-core-capability_broker`; workers never perform side effects directly.
- INV-2: `core.*` never imports `pack.*` code in-process; external packs execute only across the worker boundary.
- INV-3: every mutating action is performed only by the current `R-held_by` lease holder; non-holders are read-only.
- INV-4: every mutating action is `R-attributed_to` a `trusted` actor; `unknown`/`revoked` actors are read-only.
- INV-5: a live provider call requires ALL of: resolved `credential_ref` + matching `entitlement_tier` + provider-profile cap + `budget_envelope <= cap` + cleanup proof.
- INV-6: no raw secret appears in any manifest, event, artifact, log, or screenshot; only `credential_ref`.
- INV-7: state SSOT is SQLite-WAL (R2.4); JSON/JSONL manifests are exported views; boundary packages (final/handoff/evidence) are plain files.
- INV-8: every untrusted carrier (NL/HTML/PDF/DOCX/PPTX/notes/comments/metadata/tool descriptors/MCP-A2A messages/peer cards/provider output/web) is data, not instruction; it alone cannot change goal/tool/budget/destination.
- INV-9: `accepted` != `finalized` != `remembered`; each is a separate explicit gate.
- INV-10: provider-job lifecycle/polling/terminal outcome are core-scheduler-owned; workers are stateless across polls.
- INV-11: a handoff refreshes only at stable checkpoints (`initial_brief_submitted|review_ready|feedback_action_saved|final_package_created`) and excludes chat/secrets/browser state.
- INV-12: no post-handoff spend/job/rerun/finalize occurs before `E-core-resume_confirmation` is recorded.
- INV-13: the `event_log` is the audit source; a snapshot is never the audit source and never silently deletes original events.
- INV-0: this plan never authorizes implementation by itself; explicit user approval for the next spec-driven stage is required, and `/speckit-taskstoissues` is the only source of executable implementation and verification tasks.
- INV-14: an external pack is enablement-eligible only after register + schema-validate + security-inventory + allowlist + workspace/user enable + source-refreshed CycloneDX/SPDX attestation.
- INV-15: a domain pack acts only within declared + granted + effective scope; undeclared capability use is denied.
- INV-16: a non-idempotent side effect is never auto-retried; duplicate `idempotency_key` replays the recorded terminal result.
- INV-17: free-form LLM prose never authorizes a transition; only a validated `M-core-decision_manifest` does.
- INV-18: an external domain-pack worker runs only inside a verified sandbox backend (WASI / container / seccomp / Seatbelt, per R2.11); if no backend is available, external execution fails closed.
- INV-19: every external input edge records `carrier_type`, `taint_origin`, `instruction_authority=false`, `trusted_intent_ref`, and `policy_decision_ref` in `M-sec-taint_map` before it can influence any decision, side effect, or LLM call.
- INV-20: every live provider call performs an atomic `M-sec-spend_ledger` reservation before submission and reconciles estimated-vs-actual spend on terminal outcome.
- INV-21: every localhost UI session uses `M-sec-local_ui_policy` with `Cache-Control: no-store`, one-time token burn, tokenless redirect after consume, raw-token log redaction, and no raw token in evidence/screenshots.
- INV-22: MCP tool/resource/prompt descriptions and annotations never reduce confirmation, grants, or broker gates unless `M-proto-mcp_adapter_manifest.server_trust_state=trusted` and `M-proto-mcp_tool_inventory` diff approval is recorded.
- INV-23: `CAP-external_agent_task` is denied unless `M-proto-a2a_peer_manifest` verifies the signed Agent Card, revocation state, and task/artifact scope; card descriptions, skills, and examples remain tainted data.
- INV-24: no external domain pack, worker, model, dataset, prompt template, workflow, tool descriptor, or provider adapter can be enabled, packaged, or reused unless represented in `M-sec-aibom_manifest` and linked from `M-core-security_inventory`.
- INV-25: the first live autopilot batch and every unknown/high-cost live provider attempt require `M-core-cost_estimate` before `M-sec-spend_ledger` reservation; unknown cost, price drift, estimate above the approved envelope, missing creator budget acknowledgement, or stale price schedule opens targeted budget follow-up before spend.
- INV-26: SQLite-WAL mutation is allowed only when `M-core-state_environment` proves same-host local filesystem semantics; network filesystems, cloud-sync folders, Docker/VM shared volumes with unverified lock semantics, SSHFS/NFS/SMB, or remote mounts fail closed for live spend/finalization and must use A2A/export handoff instead.

## Scope
### Must have
- A Skill-compatible package contract suitable for `npx skills add` installation and cross-agent use.
- A deterministic CLI protocol with JSON input/output so different LLM agents can run the same harness without host-specific assumptions.
- A persistent workspace state model for objective, assets, workflow plan, jobs, outputs, user feedback, and loop decisions.
- A domain-pack contract that separates reusable harness responsibilities from workload-specific behavior: resolver, planner/patcher, validator, adapter, human-review renderer, finalizer, memory policy, and QA fixtures.
- A harness-core reference fixture that proves the Skill/CLI/state/handoff loop works without relying on Civitai, Comfy, images, or visual-gallery assumptions.
- Q19 domain-pack boundary policy: image generation ships as a built-in reference domain pack, but core cannot call Civitai/Comfy/image logic except through `domain_pack_manifest.json` and the generic domain-pack interface.
- Q20 domain-pack registration policy: built-in packs may be bundled, but future non-image packs load only after explicit install/register, schema validation, version/source recording, security inventory, allowlist approval, and workspace or user config enablement.
- Q21 domain-pack permission policy: registered packs receive least-privilege capability grants in human-readable groups; workspace settings can narrow user-level grants, and undeclared capabilities are denied by default.
- Q22 domain-pack execution isolation policy: external packs execute out-of-process through a JSON IPC/CLI worker contract; built-in packs may be bundled but must satisfy the same interface, and workers receive only effective granted env/file/provider/budget/memory scopes.
- Q23 side-effect brokerage policy: workers emit typed side-effect requests, and core capability brokers perform provider/network/file/budget/memory/tool/agent operations only after effective-scope, budget, credential-ref, trace, output-inspection, and evidence checks.
- Q24 broker idempotency/retry/cancel policy: every side-effect request carries `idempotency_key`, explicit `retry_policy`, `timeout`, `cancel_token`, lifecycle events, and a terminal outcome; core never retries non-idempotent effects blindly.
- Q25 provider job ownership policy: core scheduler owns durable provider-job leases and polling after broker approval; broker execution may return `pending` with a provider job ref, while `job_manifest.json`, `event_log.jsonl`, and `side_effect_result.json` record resume handles, lease owner, polling cadence, cancel token, and terminal outcome.
- Q26 scheduler lease concurrency policy: single-writer workspace/job leases with heartbeat and TTL gate submit, poll, cancel, and finalize; stale leases are recovered with event-log evidence, and non-holder agents receive read-only status/resume surfaces until they acquire the lease.
- Q30 actor identity/trust policy: use local trust registry with generated per-host/agent identity. Each host agent has stable `agent_id`, `agent_session_id`, human-visible label, host/runtime/version, optional signing key fingerprint, workspace grant status, and trust state. Unknown agents may read handoff/status but need explicit approval before lease acquisition or budget-spending mutation.
- Q31 retention/cleanup policy: use retention classes with a creator-facing cleanup screen; final packages and opt-in project memory persist until explicit deletion, handoff/status packages persist until superseded or finalized, event logs/snapshots persist until retention permits compaction, raw intermediates/temp renders/provider caches are pruned only after reproducibility and handoff proofs exist, and all deletions write tombstone events.
- Q32 LLM decision execution policy: use host-agent-first typed decision/proposal manifests by default; harness-owned model calls are optional brokered side effects with provider profile, budget, input hash, model id, output schema, trace, actor/trust, credential ref, and evidence.
- Q33 live-provider execution policy: first implementation and QA are live-provider-first when credentials exist; real provider paths should run when credential profile, budget envelope, actor trust, lease, idempotency, and cleanup gates pass, while mocks/fixtures remain explicit fallback for missing credentials, forced offline mode, deterministic unit tests, and failure fixtures.
- Q34 live-provider spend guardrail policy: each credential profile declares hard live caps such as `max_live_smoke_spend`, `max_live_jobs`, `max_live_wall_clock`, and cleanup requirements; live execution blocks and opens a budget/setup prompt when the cap is missing; workspace budget must fit within the provider-profile cap.
- Q34a pre-spend estimate policy: before the first live autopilot batch, and before any unknown/high-cost live provider attempt, the harness writes `M-core-cost_estimate` and blocks for targeted budget follow-up when cost is unknown, price schedule is stale, estimate exceeds the approved envelope, or the initial creator brief did not explicitly acknowledge the live-spend envelope.
- Q35 CI/live-provider check policy: default CI and PR checks stay mock/offline even when credentials and caps exist; live provider checks run only through manual, scheduled, label-gated, or env-gated jobs with provider-profile cap and cleanup evidence; local executable demos remain live-first.
- Q36/Q37 non-image proof policy: first implementation includes `presentation_document_pack` as the real second non-image production domain pack, not only a fixture or static boundary test; it must prove the shared lifecycle without Civitai, Comfy, image files, graph-patch taxonomy, or gallery-specific assumptions.
- Q37 locked: choose presentation/document production as `presentation_document_pack`. It should prove a non-image lifecycle with brief, outline, deck/doc plan, editable/source-native artifact, localhost review, saved revision/accept action, final package, and handoff. Data/report/dashboard is the preferred third pack; code/repo automation is deferred to a later security-heavy pack.
- Q27 durable state substrate policy (per R2.4; supersedes the former file-first wording): **SQLite in WAL mode is the authoritative source of truth** - an append-only `event_log` table + audit-hash columns + an ownership/lease row. Append-only JSONL event logs and JSON manifests are **exported views** written for handoff, finalization, cross-agent resume, and evidence, not the primary store. SQLite ACID/WAL provides atomicity, single-writer exclusion, and crash recovery (same-host scope, R2.6), replacing hand-rolled file locks / atomic-rename / checksum chains. Temporal/hosted DBs remain optional export-compatible adapters only.
- Q27a state environment policy: every mutating workspace must record `M-core-state_environment`; live spend/finalization fails closed on network filesystem, cloud-sync folder, remote mount, or container/VM shared-volume lock semantics that cannot be proven safe for SQLite WAL.
- Q28 snapshot/migration policy: append-only event logs remain the audit source; periodic `snapshot_manifest.json` files record `schema_version`, covered event ranges, checksum chains, and `migration_ledger.json` references; compaction cannot silently delete original events before final-package or handoff retention rules allow it.
- Q29 localhost UI session security policy: `serve-intake`, `serve-review`, and `resume` bind loopback-only by default; generated URLs include random one-time session tokens with short TTLs; mutating actions require CSRF token plus origin check; static artifacts are read-only unless an action token allows mutation; saved actions still pass CLI/state lease and policy checks.
- A 2026 architecture reference model in the implementation spec: Agent Skills for package/installability, deterministic CLI/state core, domain-pack interface, project-selected AG-UI event-vocabulary browser surfaces, A2A only for optional remote-agent task/artifact interop, MCP only for optional tool/data interop, direct provider adapters, durable event state, observability, and security inventory. Comfy/Civitai direct adapters belong to the first image domain pack.
- Image domain-pack link and workflow resolvers for Civitai model/version/download/AIR links, Hugging Face file links, Comfy workflow JSON, Comfy image metadata, Comfy Cloud share links, and Civitai image/post links with confidence levels.
- An image domain-pack workflow importer that preserves `original.workflow.json` / `original.api.json`, extracts model links and missing-node requirements, and validates the original on the selected Comfy surface before mutation.
- A typed reference-intent router that distinguishes asset import, exact reproduction candidate, workflow import, source transform/edit, structure/control, identity/object consistency, style/mood reference, and reference-board-only mode.
- A graph patch engine that converts creator intent into validated node additions or edits using a taxonomy: `asset_model_binding`, `prompt_text_conditioning`, `sampler_latent_policy`, `structure_spatial_control`, `reference_identity_style`, `source_image_edit`, `segmentation_mask_routing`, `detail_refine_enhance`, `custom_node_dependency`, `external_provider_or_partner_route`, and `evaluation_feedback_loop`.
- Representative instances such as ControlNet, LoRA, SAM, IPAdapter, detailer, refiner/upscaler, model-loader replacement, and supported custom-node insertion must be modeled as examples under that taxonomy, not as the complete feature set.
- Q7/Q9 autonomy policy: after original and patched workflow validation pass, graph patches execute automatically inside the workspace `budget_envelope` only after the pre-spend estimate gate passes; envelope overrun, unknown cost, stale price schedule, missing budget acknowledgement, missing credits/Buzz, credentials, unsupported capabilities, rights/safety, or genuine creative ambiguity interrupts execution.
- A localhost browser questionnaire surface for creator-facing intake and clarification. Q8/Q9 policy: run one lightweight initial brief at workspace start, collect budget limits there, then reopen only for targeted ambiguity/risk/budget follow-ups. It must ask in creator vocabulary about usage context, desired mood/style, composition, reference role, product/brand constraints, design elements, acceptable changes, example applications, output format, review priorities, and budget envelope.
- A `ppt-master`-style credential profile: current process environment wins, provider-specific keys are used (`COMFY_CLOUD_API_KEY`, `CIVITAI_API_TOKEN`, optional OpenAI-compatible provider keys), persistent user config is allowed, and workspace artifacts record only `credential_ref` plus non-secret provider metadata.
- Initial recipe families for controlled text-to-image, controlled image-to-image, localized edit/inpaint, reference composition, and refine/upscale.
- Execution routing for Comfy Cloud API, Civitai orchestration/Skill handoff, and reference-board mode; local ComfyUI is excluded from the product runtime and may appear only as a mocked adapter in tests.
- Q11 review policy: a result review surface using a localhost gallery for comparison, selection, feedback, and proposal cards, plus static HTML, `result_manifest.json`, `review_gallery_session.json`, image grid/contact sheet, and per-image sidecar metadata.
- Q12 post-result iteration policy: after every rendered batch, state becomes `review_open` / `proposed` / `creator_action_required`. The LLM evaluator may rank outputs and create proposal cards, but accept, rerun, refine, branch, or continue requires explicit creator action saved in `feedback.json` / `loop_state.json`.
- Q13 acceptance package policy: when the creator accepts, `finalize` writes a reproducibility package containing accepted image files, static review page, original and patched workflows, graph patch diff, prompts/settings, provenance, cost/budget summary, rights/license notes, and `final_package_manifest.json`.
- Q14 project memory policy: accepted results become reusable project memory only when the creator opts in from the gallery. Store selected style, brand/product constraints, or workflow reuse as managed references in `project_memory_manifest.json`, pointing to the accepted `final_package_manifest.json` with source hash, allowed reuse scope, rights policy, creator-visible label, and deletion support.
- Q15 project memory application policy: saved project memory profiles appear as visible cards in the next workspace `initial_brief`, and only creator-selected cards may influence that workspace's `creator_intake.json`, `workflow_plan.json`, or graph patch planning. No profile is auto-selected or silently applied.
- Q16 cross-agent handoff policy: continuation uses a clean `handoff_manifest.json` package with current status, allowed next actions, required manifests, selected review/final artifacts, chosen memory refs, trace/evidence pointers, and exclusion checks. It must not include chat transcript, raw secrets, hidden browser state, or unsaved browser-only selections.
- Q17 handoff refresh timing policy: create or refresh `handoff_manifest.json` only at stable checkpoints: after initial brief submission, after a rendered batch enters review/creator-action-required, after feedback/action is saved, and after final package creation. Do not continuously export every internal state change or wait for manual export before checkpoint handoffs.
- Q18 handoff resume policy: when a future agent/session opens `handoff_manifest.json`, it must first show a short "continue this work?" screen with current status, allowed/recommended next action, budget remaining, selected memory refs, and blockers. No resumed agent may spend budget, submit a provider job, rerun, refine, branch, or finalize until the human confirms that screen.
- A user-intent loop with explicit satisfaction checks, feedback capture, budget/iteration controls, and termination reasons.
- Issue-backed QA evidence for happy paths and failure paths, generated only after the approved spec/task workflow creates concrete implementation issues.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- Do not build a new MCP server as the main product. MCP can be an optional adapter only.
- Do not let image generation, Civitai, Comfy, gallery UX, or creator-memory features become the product boundary. They are reference-domain behavior under the Cross-Agent LLM Execution Harness.
- Do not directly import, instantiate, or special-case Civitai/Comfy/image code from harness core. All image behavior must pass through the domain-pack registry and `domain_pack_manifest.json`.
- Do not load arbitrary local folders solely because they contain a valid-looking `domain_pack_manifest.json`; external packs must be registered, schema-validated, versioned, security-inventoried, allowlisted, and enabled by workspace/user config first.
- Do not enable external domain packs by default or let a disabled/unregistered pack contribute resolver, planner, adapter, review, memory, or finalizer behavior.
- Do not trust a registered pack with all harness capabilities by default, do not prompt on every individual action as the default workflow, and do not let a pack use provider/network, file, localhost UI, memory, budget, tool, or agent access beyond its declared and granted scopes.
- Do not import external domain-pack executable code directly into the core process, and do not give workers ambient environment variables, full workspace filesystem, hidden browser state, or unscoped credentials.
- Do not let workers directly perform provider calls, network requests, file writes, budget spend, project memory mutation, or external tool/agent calls; those side effects must go through core capability brokers.
- Do not allow ambient retries, duplicate provider submissions, repeated file/memory writes, or cancellation-by-convention; brokered effects require explicit idempotency, retry, timeout, cancel, lifecycle, and terminal-outcome records.
- Do not let workers own hidden provider polling loops or keep long-running provider state only in worker runtime memory; provider-job leases, polling, cancellation, and terminal outcomes are core scheduler state.
- Do not treat snapshots as the audit source, silently delete original events during compaction, apply schema migrations without a migration ledger, or resume from a snapshot whose covered event range and checksum chain cannot be verified.
- Do not bind localhost creator/review/resume UI to LAN or `0.0.0.0` by default, accept mutating browser requests without one-time session token plus CSRF plus origin check, persist raw session tokens in artifacts, or let browser tokens bypass CLI/state lease and policy checks.
- Do not rely on free-form actor strings, process names, or chat transcript identity for event authorship, lease ownership, broker approval, UI confirmation, or handoff resume authority; unknown or untrusted agents must stay read-only until explicitly trusted for the workspace.
- Do not delete final packages, project memory, handoff/status packages, event logs, snapshots, or intermediates without retention-class checks, proof checks, actor/lease authority, creator-visible cleanup state where applicable, and tombstone events; raw secrets must never be persisted just to support later audit or cleanup.
- Do not put a hidden harness-owned LLM router inside the deterministic core, silently call model providers for planning decisions, or accept free-form LLM prose as execution authority; decisions must be typed manifests, and harness-owned model calls must be brokered side effects with budget, credential, schema, trace, and evidence.
- Do not allow concurrent agents to submit, poll, cancel, or finalize the same workspace/job without holding the active lease; do not rely on optimistic multi-writer reconciliation for paid provider operations.
- Do not make a networked/hosted DB or a remote service queue the source of truth (it breaks portability and same-host resume). Per R2.4 the authoritative store is local embedded **SQLite in WAL mode**, which MUST export canonical JSON/JSONL manifests/events for handoff and cross-agent resume. Temporal/hosted DBs are allowed only as optional export-compatible adapters, never as the primary store. (This reverses the earlier "do not use SQLite as source of truth" wording, which conflicted with R2.4.)
- Do not use SQLite-WAL live mutation on network filesystems, cloud-sync folders, remote mounts, or container/VM shared volumes unless `M-core-state_environment` proves same-host local locking semantics; use export/A2A handoff instead.
- Do not depend on one host agent's private features; Codex, Claude Code, and other Skill-compatible agents must share the same CLI/state contract.
- Do not conflate Agent Skills, AG-UI, A2A, MCP, direct provider APIs, and durable workflow runtimes. Each boundary must have its own contract and evidence.
- Do not discard an importable Civitai/Comfy workflow in favor of a generic template.
- Do not default to raw LLM graph construction for all Comfy nodes.
- Do not let the LLM hallucinate arbitrary node JSON; graph mutations must be typed patch operations backed by `object_info`, supported-node inventory, templates, subgraphs, or imported workflow schema.
- Do not hard-code ControlNet, LoRA, SAM, and IPAdapter as the full capability list; they are representative examples under broader graph augmentation families.
- Do not ask creators developer-language questions about nodes, graph patches, samplers, denoise, or model-control primitives. Technical uncertainty must be translated into creator-facing choices.
- Do not present ambiguity questions only in the terminal; the user-facing clarification surface is a localhost browser questionnaire.
- Do not force a full questionnaire before every execution after the initial creator brief; follow-up intake must ask only the unresolved creative, rights, cost, credential, or capability question.
- Do not spend Comfy Cloud credits, Civitai Buzz, or other paid provider budget outside the approved workspace `budget_envelope`; ask a targeted budget follow-up instead.
- Do not use the workspace `budget_envelope` alone to bypass a missing or lower provider-profile live cap, and do not let agent decisions, creator intake, or workspace config silently raise live caps.
- Do not submit the first live autopilot batch or an unknown/high-cost live provider job without a recorded `M-core-cost_estimate` and budget acknowledgement; unknown cost, stale price schedule, or estimate above envelope opens targeted budget follow-up before spend.
- Do not run live providers from default CI/PR checks merely because credentials and provider-profile caps exist; live checks must be manual/scheduled/label/env gated with provider-profile cap evidence and cleanup evidence.
- Do not treat a non-image fixture, static boundary test, or image-pack import check as sufficient generality proof after Q36; the first implementation needs a production-grade second domain pack with observable review, finalization, and handoff artifacts.
- Do not silently fall back to mocks when a credentialed live-provider path is expected; every mock/offline fallback must record a reason such as missing credential, explicit offline flag, deterministic unit test, or failure fixture.
- Do not put raw API keys, tokens, `.env` contents, or Authorization headers in workspace files, result manifests, evidence logs, rendered reports, graph patch manifests, screenshots, or PR artifacts.
- Do not use one generic secret such as `IMAGE_API_KEY` for all providers; provider-specific names and explicit active provider/profile selection are required.
- Do not claim exact reconstruction from Civitai image/post links unless metadata and resources are resolved.
- Do not execute a bare Civitai image/post link as exact reproduction without explicit user intent and resolver evidence.
- Do not hide uncertainty; every workspace must record exact, partial, or reference-only reproducibility confidence.
- Do not rely on terminal summaries, raw image paths, or browser-only state for result review; the gallery and all feedback must have durable static artifacts.
- Do not automatically rerun low-confidence outputs, refine images, branch variants, accept results, or submit a next job after rendering unless the creator explicitly selected that action in the gallery.
- Do not treat final images alone as the accepted deliverable; final acceptance must preserve workflow, graph patch, prompt/settings, provenance, cost/budget, rights/license, and checksum metadata for reproduction and cross-agent handoff.
- Do not auto-save every accepted output as project memory, do not derive reusable memory from browser localStorage or chat transcript, and do not reuse remembered style/brand/workflow profiles outside their allowed reuse scope or rights policy.
- Do not silently auto-apply saved project memory to new workspaces, do not preselect memory cards by default, and do not apply disabled, deleted, rights-blocked, or out-of-scope profiles.
- Do not include chat transcripts, raw API keys, Authorization headers, `.env` contents, browser localStorage/sessionStorage, hidden browser state, unsaved browser-only selections, or unbounded intermediate artifacts in cross-agent handoff.
- Do not refresh handoff packages after every low-level state write, provider poll, model/tool token event, browser hover, temporary selection, or unsaved UI interaction.
- Do not allow post-handoff auto-continue, provider spend, job submission, rerun/refine/branch, or finalization before the human confirms the resume screen.
- Do not skip the user's global spec-driven workflow before code implementation.
- Do not use generated images as final proof without rendering them through the review surface.
- Do not silently spend cloud credits/Buzz or launch long jobs without budget/approval gates.

## Verification strategy
> Agent-executed evidence by default. Human approval remains required at workflow approval gates, resume confirmation, and creator action gates; manual QA means the agent drives the real Skill/CLI/UI surface and records evidence.
- Test decision: behavior/contract tests are written before or alongside CLI and adapter implementation; artifact-level manual QA gates remain required for rendered/reviewed results.
- Generic lifecycle QA: every domain pack must map onto `workspace_created -> domain_pack_selected -> intake_submitted -> inputs_resolved -> domain_plan_created -> domain_plan_validated -> preflight_checked -> execution_prepared -> submitted|running|pending -> artifacts_ready -> review_open -> human_action_required -> action_saved -> continued|accepted|blocked|stopped -> final_package_created -> handoff_refreshed -> completed`.
- Harness-core QA: the selected Q37 second non-image production domain pack must drive the same `init -> resolve -> plan-workspace -> gate -> run -> review -> feedback -> finalize -> handoff` command lifecycle far enough to prove the domain-pack boundary is real without relying on Civitai, Comfy, image files, graph-patch taxonomy, or visual-gallery assumptions.
- Presentation-pack QA: `presentation_document_pack` must map its substates to `brief_resolved -> outline_created -> source_material_resolved -> deck_doc_plan_created -> editable_artifact_created -> review_snapshot_created -> revision_action_saved -> revised|accepted -> final_package_created`.
- Domain-boundary QA: tests or static checks verify core modules call domain packs only through the registry/interface and reject direct imports or hard-coded image-pack assumptions in core.
- Domain-pack registration QA: tests verify built-in packs are bundled explicitly and future non-image packs are denied until registered, schema-validated, versioned, security-inventoried, allowlisted, and enabled in workspace/user config.
- Domain-pack permission QA: tests verify declared, granted, and effective capability scopes; workspace config can narrow user-level grants; undeclared provider/network/file/UI/memory/budget/tool/agent access is denied before execution.
- Domain-pack supply-chain QA: tests verify external packs and worker bundles require publisher identity, signed provenance or equivalent attestation, immutable digest, pinned lockfile, SBOM/AIBOM, dependency vulnerability scan, typosquat/dependency-confusion checks, install-script policy, revocation/quarantine state, and update-diff review before enablement.
- Domain-pack worker QA: tests verify external pack commands execute through JSON IPC/CLI workers under sandbox policy evidence, core rejects direct in-process imports for external packs, worker requests carry trace/idempotency/effective-scope envelopes, and only scoped env/file/provider/budget/memory values are projected into the worker.
- Worker sandbox QA: tests verify no ambient env inheritance, deny-by-default egress, broker-only network/provider/file/memory operations, read-only inputs, per-run temp output root, realpath checks, symlink and `../` traversal denial, archive/decompression limits, CPU/memory/fd/process/time limits, and child-process kill-tree cleanup.
- Side-effect broker QA: tests verify workers can only emit typed `side_effect_request` payloads, core brokers enforce effective scope, budget, credential refs, output inspection, idempotency key, retry policy, timeout, cancel token, lifecycle event sequence, terminal outcome, trace/evidence, and workers cannot directly write files, mutate memory, spend budget, call providers, open network, or invoke tools/agents.
- Prompt-carrier QA: tests verify all natural-language, HTML, PDF/DOCX/PPTX, slide notes/comments, image metadata, workflow labels, tool descriptors, MCP/A2A messages, peer-agent cards, provider outputs, and web content are treated as data, not instructions; proposed actions that change goals/tools solely from untrusted content are blocked.
- LLM decision boundary QA: tests verify host agents write typed `decision_manifest.json` / `proposal_manifest.json`, scheduler consumes only validated decision/proposal manifests, free-form LLM text cannot authorize transitions, and any harness-owned model call is approved only as an `llm_model_call` brokered side effect with `llm_call_manifest.json`, provider profile, model id, input/output hashes, output schema, budget, credential ref, actor trust, trace, and evidence.
- Provider-job scheduler QA: tests verify broker execution can return `pending`, core scheduler records provider job refs/resume handles/lease owner/polling cadence/cancel token/terminal outcome, polling resumes from manifests after process restart, and workers remain stateless.
- Scheduler lease QA: tests verify only the active lease holder can mutate workspace/job state, heartbeat extends ownership, TTL enables stale-lease recovery with event-log evidence, and non-holder agents can only read status/resume screens.
- Actor identity/trust QA: tests verify stable `agent_identity.json` creation, trust-registry lookup, unknown-agent read-only behavior, explicit workspace grant flow before lease acquisition or budget spend, actor attribution on events/leases/broker requests/UI confirmations, and rejection of spoofed free-form actor ids.
- Durable state QA (per R2.4; replaces "file-first state QA"): tests verify the SQLite-WAL store (append-only `event_log` table, audit-hash chain, single-writer/ownership row, ACID atomicity, crash recovery), that `M-core-state_environment` rejects unsafe filesystem/container shared-volume cases, that exported JSON/JSONL manifests round-trip losslessly for handoff/finalization, plus corruption detection and optional adapter-export compatibility. SQLite-transaction tests supersede hand-rolled file-lock/atomic-rename tests.
- Snapshot/migration QA: tests verify `state snapshot` writes `snapshot_manifest.json` with schema version, covered event range, checksum chain, and migration-ledger refs; replay from event log and replay from snapshot plus tail events produce equivalent state; schema migration requires `migration_ledger.json`; retention/compaction refuses to delete original events before final-package or handoff retention allows it.
- Retention/cleanup QA: tests verify artifact retention classes, creator-facing cleanup review, proof-gated pruning of raw intermediates/temp renders/provider caches, deletion tombstone events, final-package/project-memory deletion support, and denial of cleanup when reproducibility or handoff proof is missing.
- Localhost UI session QA: tests verify `serve-intake`, `serve-review`, and `resume` bind only to loopback by default, reject malicious Host headers and DNS-rebinding attempts, deny CORS by default, escape/sanitize rendered metadata, emit one-time token URLs without persisting raw tokens, enforce short TTLs, require CSRF plus origin checks for mutating actions, send CSP/referrer/content-type/frame protections, keep static artifacts read-only by default, and re-run CLI/state lease checks before saving feedback, intake, or resume confirmation.
- Unit tests: parser/resolver/schema tests for Civitai/HF/Comfy links and manifests.
- Contract tests: CLI commands accept JSON input and emit stable JSON output across agents.
- Fixture tests: Civitai model link, model version link, AIR URN, metadata-rich image link, metadata-missing image link, workflow-bearing image/link, and unsupported-node workflow.
- Questionnaire QA: localhost intake page renders the initial creator brief, records answers including `budget_envelope`, shows available saved memory cards when present, records only creator-selected memory profiles, maps answers into machine-readable intent/feedback files, supports targeted follow-up sessions, and never exposes raw developer terms unless technical mode is explicitly enabled.
- Integration tests: live Comfy Cloud/Civitai/provider path first when credential profile with a configured hard live cap, budget envelope within that cap, actor trust, lease, and idempotency gates pass; mocks/fixtures are used for missing credentials, missing provider-profile cap, forced offline mode, deterministic unit tests, and failure scenarios, and must record the fallback reason.
- CI/check QA: default CI and PR checks must run mock/offline fixtures only and require no provider credentials; live provider checks are separate manual/scheduled/label/env-gated jobs that record gate source, provider-profile cap snapshot, cleanup evidence, terminal provider status, and fallback/block reasons.
- Spend-abuse QA: live-provider tests update a credential-profile budget ledger, require `M-core-cost_estimate` before first live autopilot/unknown-cost jobs, enforce rolling daily/monthly spend, per-provider-account caps, per-workspace caps, per-actor/domain-pack quotas, concurrent-job limits, estimated-vs-actual reconciliation, failure-rate circuit breaker, price-drift block, stale-pending cleanup, and operator kill switch.
- Secret-handling QA: provider credentials can be loaded from process env or persistent user config, but generated workspace artifacts contain only `credential_ref`; evidence scans reject raw API-key patterns and Authorization headers.
- Render QA: generated or fixture images produce a non-empty localhost review gallery, contact sheets, static HTML, `review_gallery_session.json`, `result_manifest.json`, and sidecar metadata with matching image IDs.
- Loop QA: simulate accept, revise, budget stop, plateau stop, blocked stop, unsafe/license stop, gallery feedback submission into `feedback.json`, and Q12 no-auto-rerun behavior where low evaluator confidence creates proposal cards but no next job until a saved creator action exists.

- Registered domain packs operate under least-privilege capability grants: human-readable permissions are visible during registration/enablement, workspace config can narrow grants, and undeclared or ungranted capabilities fail before execution.
- External domain-pack executable code runs out-of-process behind a JSON IPC/CLI worker interface, with only effective granted env/file/provider/budget/memory scopes projected into the worker and no direct imports into harness core.
- Worker side effects are brokered by core: provider calls, network access, file writes, budget spend, project memory writes, and external tool/agent calls happen only after core capability broker approval and evidence recording.
- Brokered side effects are lifecycle-safe: every request has explicit idempotency, retry, timeout, cancel, lifecycle, and terminal-outcome records; duplicate submissions cannot silently create duplicate provider jobs or repeated file/memory writes.
- Long-running provider jobs are core scheduler state: provider job refs, resume handles, lease owner, polling cadence, cancel token, terminal outcome, and evidence are stored in manifests so another agent can resume without worker runtime memory.
- Concurrent agents are safe by default: only the active single-writer workspace/job lease holder can mutate job state; heartbeat/TTL and stale recovery are evidenced, and non-holders are read-only until they acquire the lease.
- Actor identity is explicit and local-first: every mutating action is tied to a stable trusted `agent_id` plus current `agent_session_id`, unknown agents can inspect only read-only status/handoff, and free-form actor strings or chat transcript identity never authorize leases, budget spend, memory writes, handoff mutation, resume confirmation, or finalization.
- Durable state is portable and inspectable: per R2.4 the first implementation uses **SQLite in WAL mode as the source of truth** (an append-only `event_log` table plus audit-hash columns and an ownership/lease row) and **exports** canonical JSON manifests + a JSONL event log for handoff, finalization, and cross-agent resume. Hand-rolled cross-platform file locking, temp+rename atomicity, and manual checksum chains are replaced by SQLite's ACID/WAL guarantees (same-host scope per R2.6); Temporal/hosted DBs remain optional export-compatible adapters only.
- Snapshot and migration behavior preserves auditability: snapshots speed resume but the append-only event log remains authoritative, migrations are recorded in `migration_ledger.json`, replay equivalence is tested, and compaction is retention-gated.
- Retention and cleanup behavior balances auditability and storage: final packages/project memory persist until explicit deletion, handoff/status artifacts persist until superseded/finalized, intermediates are pruned only after proof checks, cleanup is visible to the creator, and every deletion leaves a tombstone event.
- LLM decision execution stays deterministic: host agents write typed decision/proposal manifests, free-form LLM prose is never authority, and any harness-owned model call is a brokered, budgeted, schema-validated side effect with evidence.
- Live provider behavior is real when credentials exist: credentialed workspaces and demos default to live provider execution after gates pass, while mock/offline paths are explicit fallback lanes with recorded reasons and no silent confidence substitution.
- Live provider spend is capped at the provider profile: credentialed live execution requires `max_live_smoke_spend`, `max_live_jobs`, wall-clock cap, cleanup requirements, and cap evidence, and workspace budgets cannot bypass or raise that cap.
- CI remains deterministic by default: PR/default checks use mock/offline fixtures, while real provider drift is verified only by explicitly gated live checks with provider-profile caps and cleanup evidence.
- Localhost browser surfaces are convenient but not ambient authority: intake, review, and resume sessions are loopback-only by default, use one-time token URLs with CSRF/origin checks, persist no raw tokens, keep static artifacts read-only unless action-scoped, and revalidate CLI/state leases before state mutation.
- A real second non-image production domain pack, `presentation_document_pack`, proves the same state/handoff/review/finalization loop with editable/source-native PPTX/DOCX/Markdown/HTML artifacts, static review/export evidence, source-material rights checks, revision actions, and clean handoff, without Civitai, Comfy, image files, graph-patch taxonomy, or visual-gallery assumptions.
- In the image domain pack, a Civitai/Comfy workflow-bearing link can create an original workflow snapshot, validate it, compile graph patches, and execute the patched workflow route.
- Every workspace opens one lightweight initial localhost creator brief that asks about usage context, mood/style, design elements, references, examples, constraints, output formats, budget envelope, rights, and available saved memory cards in creator-facing wording; later ambiguity, risk, or budget gates open targeted follow-ups only.
- Provider credentials are configured like `ppt-master`: provider-specific environment/user-config keys, explicit active provider/profile, process env precedence, and workspace manifests containing only `credential_ref`.
- A Civitai model/version/download/AIR link can create a workspace manifest and choose a valid fallback recipe route when no workflow exists.
- A Civitai image/post link with missing workflow metadata becomes reference-board mode, not a fake exact workflow.
- A generated batch renders into a localhost review gallery plus static HTML/result manifest artifacts with stable image IDs, metadata, selectable candidates, saved feedback, proposal cards, and `creator_action_required` state.
- The loop can continue only from saved creator gallery action and terminates only through explicit stop conditions.
- A creator-accepted result writes a full reproducibility package with `final_package_manifest.json`, final images, static review page, workflow bundle, graph patch diff, prompt/settings, provenance, cost/budget summary, rights/license notes, and checksums.
- Project memory is opt-in and per-workspace explicit: accepted style, brand/product constraints, or workflow reuse is saved only when the creator chooses it, stored as a managed `project_memory_manifest.json` reference to the final package, can be disabled or deleted, and is applied in a later workspace only when the creator selects its visible initial-brief card.
- Cross-agent handoff is clean: another agent or future session can resume from `handoff_manifest.json` and referenced manifests/artifacts without chat transcript, raw secrets, hidden browser state, or unbounded intermediate dumps.
- Handoff refresh is checkpointed: `handoff_manifest.json` is current at initial-brief submission, review-ready pause, saved feedback/action, and final package creation, without continuous export noise.
- Handoff resume is human-confirmed: a resumed agent must show current status, next action, budget remaining, selected memory refs, and blockers before spending budget or submitting a new job, and the confirmation is recorded in `resume_confirmation.json`.
- All tasks have agent-executed evidence, including happy and failure paths.
